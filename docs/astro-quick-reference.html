The one rule

Parameters decide, not names. A run with an interval and a bound (frames or duration) is a timelapse. Anything else is a single shot. Partial timing is rejected, not guessed.

Capture

/astro captureOne frame, active profile
/astro capture profile=<name>Use a named profile
/astro capture exposure=S iso=N frames=NOverride anything
/astro capture interval=S duration=S…makes it a timelapse
/astro preview exposure=S iso=NQuick daylight frame
/astro lastResend last frame
/astro abortStop the run
/astro statusState, camera, active profile
Abort waits. It stops between frames — an exposure already running finishes first.

Exposure ramping

iso_start= iso_end=ISO across the ramp
exposure_start= exposure_end=Exposure across the ramp
ramp_duration=SRamp, then hold at the end values
Works on any profile or command. Ramps logarithmically, so 100→200 takes the same frames as 1600→3200.

From capture to video

capture → archive session → render

Frames land on the Pi. Archiving is manual — and the Pi keeps only the newest 200 frames, so archive a long run before it prunes itself.
/astro sessionsRuns on the Pi, by id
/astro shots <id>Frames + thumbnails
/astro archive session <id>Copy a run to the LXD
/astro archive last | <frame>Copy one frame
/astro archived [id]Browse the archive
/astro render <id>Stitch a run into MP4
/astro delete session <id> confirmDelete from the Pi
/astro delete all confirmDelete everything

Before a session

1. Camera on, dial to M.
2. Menu → Setup → USB Connection → PC Remote. If it enumerates as “charging mode”, gphoto2 cannot see it.
3. /astro battery to confirm the link.

Rules of thumb

500 rule. Longest exposure before star trails ≈ 500 ÷ focal length. 20 mm → ~25 s.
Bulb is automatic above 30 s.
Mount control is not implemented — /astro track says so.
